## Activity 1: AI-Generated OOP Version

### Design & Paradigm Prompting
The human developer prompted the AI assistant to generate a standard Object-Oriented shopping cart. The AI modeled the cart according to classical OOP thought patterns:
- **Encapsulated State:** The internal collection of items (`#items`) lives within the instance across method calls.
- **In-Place Mutation:** Methods (`addItem`, `removeItem`) modify internal memory buffers in place using `.push()` and `.splice()`.
- **Active Entity:** The object is "a thing that holds data and knows how to act on it."

### Code Snippet: AI Implementation ([`oopCart.js`](https://github.com/Abdullah-Developer68/SDC-LAB-6/blob/main/oopCart.js))
```javascript
// Generated by AI Assistant
import { createItem } from './item.js';

export class ShoppingCart {
  static DISCOUNT_THRESHOLD = 100.0;
  static DISCOUNT_RATE = 0.10; // 10% discount above $100

  #items;

  constructor() {
    this.#items = [];
  }

  addItem(name, price) {
    this.#items.push(createItem(name, price));
  }

  removeItem(name) {
    const index = this.#items.findIndex(item => item.name === name);
    if (index !== -1) {
      this.#items.splice(index, 1);
      return true;
    }
    return false;
  }

  total() {
    const subtotal = this.#items.reduce((sum, item) => sum + item.price, 0);
    if (subtotal > ShoppingCart.DISCOUNT_THRESHOLD) {
      return subtotal * (1.0 - ShoppingCart.DISCOUNT_RATE);
    }
    return subtotal;
  }

  get count() {
    return this.#items.length;
  }
}
```

## Activity 2: Human-Crafted Functional Version & AI Critique

### Human Review: Catching AI's "Impure Functional" Trap
When asked to convert the OOP code to a functional style, AI models commonly generate functions that operate on standard mutable arrays (`array.push()` or unfrozen arrays). As emphasized in the lab prerequisites:
> *"Review the difference between mutable and immutable data structures before class — the functional half of this exercise depends on recognising when the model's 'functional' code is not actually pure."*

The human developer audited the AI's conversion and hand-crafted a **truly pure functional implementation**:
1. **Guaranteed Immutability:** Enforced via `Object.freeze()`. Any accidental mutation attempt throws a `TypeError` in strict mode.
2. **Pure Non-Destructive Transformations:** Replaced array splicing with immutable slice and spread operations (`[...cart.slice(0, index), ...cart.slice(index + 1)]`).
3. **Referential Transparency:** Every function depends exclusively on its explicit inputs with zero side-effects.

### The Two Core Paradigm Differences Confirmed by Human Audit
1. **No In-Place Mutation:** Every write operation returns a fresh immutable snapshot without altering the previous cart in memory.
2. **Zero Shared-Reference Aliasing Bugs:** In OOP, sharing an object instance between two variables (`cartB = cartA`) creates hidden coupling. In FP, data structures are immutable; shared-reference corruption is structurally impossible.

### Code Snippet: Human Implementation ([`functionalCart.js`](https://github.com/Abdullah-Developer68/SDC-LAB-6/blob/main/functionalCart.js))
```javascript
// Hand-crafted by Human Developer
import { createItem } from './item.js';

export const DISCOUNT_THRESHOLD = 100.0;
export const DISCOUNT_RATE = 0.10;

export function createCart() {
  return Object.freeze([]);
}

export function addItem(cart, name, price) {
  const newItem = createItem(name, price);
  return Object.freeze([...cart, newItem]);
}

export function removeItem(cart, name) {
  const index = cart.findIndex(item => item.name === name);
  if (index === -1) return cart;
  return Object.freeze([...cart.slice(0, index), ...cart.slice(index + 1)]);
}

export function calculateTotal(cart) {
  const subtotal = cart.reduce((sum, item) => sum + item.price, 0);
  if (subtotal > DISCOUNT_THRESHOLD) {
    return subtotal * (1.0 - DISCOUNT_RATE);
  }
  return subtotal;
}
```

## Activity 4: State Extension Trade-Off (Discount Codes)

Both models were extended with a running discount-code history (`SAVE5`, `VIP15`) across multiple calls:
- **OOP (AI Approach):** Fast and convenient. The AI added `#discountHistory = []` and mutated it in place. Callers do not need to manage state between calls.
- **Functional (Human Approach):** Clean and isolated. The human modeled an explicit state container (`{ items, discountHistory }`). State cannot hide inside objects, guaranteeing complete test isolation.

## Core Paradigm Evaluation: Simplicity, Reliability & Efficiency

| Attribute | Object-Oriented Programming (AI Model) | Functional Programming (Human Model) | Evaluation & Verdict |
| :--- | :--- | :--- | :--- |
| **Simplicity** | **High Syntactic Simplicity:** Very low ceremony for state accumulation. Adding the promo feature required adding one line to the constructor and mutating in place. | **High Cognitive Simplicity:** Each function is an isolated black box with zero hidden variables. However, requires explicit compound state container plumbing (`CartState`). | **OOP** is simpler for rapid state accumulation; **FP** is simpler for local component understanding. |
| **Reliability** | **Moderate:** Prone to **temporal coupling** (order-of-calls bug) and **aliasing hazards** (mutating `cartB` silently mutates `cartA`). | **Very High:** Complete immunity to side-effects and reference aliasing via `Object.freeze()`. Every test runs in pristine isolation with no shared leaks. | **FP wins decisively on reliability.** Immutability eliminates an entire class of production bugs. |
| **Efficiency** | **Very High:** Mutates arrays in-place (`push`, `splice`) without re-allocation. Extremely low garbage collection overhead. | **Moderate:** Spreading arrays (`[...cart, item]`) allocates new arrays and frozen wrappers on every modification, creating GC churn at extreme scale. | **OOP wins on raw computational efficiency** in unoptimized JavaScript runtimes. |
